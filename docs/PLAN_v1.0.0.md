## 2. Rules that carry over

- Nothing counts as done until it has been seen (or heard) in the real game. Reports say what was only tested.
- Every change gets a test with a negative control. Every rolled level stays bot-proven.
- Two Godot processes at most, at idle priority. Windowed captures run one at a time and stay short. Tests
  redirect APPDATA.
- Commit and push at every checkpoint, with explicit paths. Releases use `tools/build_release.ps1`,
  `tools/push_itch.bat` and `gh release`, with notes written in plain language (no em dashes).
- No sound, image or font from outside the project unless its licence is recorded in
  `THIRD_PARTY_NOTICES.md`. Music and effects are generated by our own scripts, so `docs/AUDIO.md` stays true.

## 4. Phases

### Phase 1: updater (release 0.18.0)

Model: Kinoz (`src/core/Updater.cpp`). Same promises, same wording where it fits.

- **Where it talks:** only to github.com and api.github.com for this repository, over HTTPS. Redirects may only
  lead to github.com or githubusercontent.com. The request sends nothing about the player.
- **What it installs:** only a file whose SHA-256 matches the `.sha256` file published with the release,
  checked again right before installing.
- **Modes (Settings, Gameplay):** Automatic (default: check once a day, download in the background, then ask
  "Restart now / Later"), Notify me (check and tell; download only after a click), Off (never contacts the
  network by itself; "Check for updates" in About still works).
- **Robustness:** a failed check retries after 1 hour and then 6 hours; a dropped download starts again, up to
  three tries (it does not resume part-way); the API rate limit is bypassed through the `releases/latest`
  redirect; a version can be skipped; every decision goes to the log.
- **Applying:** "Later" keeps the verified file; it is applied the next time the game starts. The apply step
  gives up after two failed attempts so a bad update can never trap the player. The launcher swaps the files,
  keeps one rollback copy and restarts the game.
- **Platforms:** Windows applies through the launcher. macOS and Linux show the notice and open the release
  page. The web and itch builds update themselves and never show the notice.
- **Release side:** `tools/build_release.ps1` writes a `.sha256` file for every zip.

Done when: tests cover a good update, a wrong hash, an interrupted download, a redirect to another host, a
skipped version, the two-attempt guard and a rollback, each with a control. Then one real update from 0.18.0 to
a test build (a GitHub pre-release) is seen working on this PC.

### Phase 2: music and sound (release 0.19.0)

Today: one 16-second music loop for all 40 levels (pitch-shifted per act) and about 20 effects, all generated
by `tools/generate_audio.py`.

- **Music:** a new generator, `tools/music_engine.py`, writes one 60 to 90 second loop per act (8), plus title,
  story, boss chase, Endless and ending. Each act gets its own key, tempo and instruments (a slow pulse for
  Cinder, glass and wind for Freezer, a storm drone for Storm, and so on). Tracks are built from stems (bass,
  pad, arpeggio, lead, drums) so the mix can react: drums join in boss chases, the lead drops out on death.
  Budget: all audio under 4 MB in the shipped pack.
- **Effects:** from about 20 to about 60. Every repeated sound gets small random pitch and volume changes so it
  never grates. New: surface footsteps, dash and wall-run layers, a death shatter and a re-roll "glitch" sound
  for the level rebuild, hazard tells, UI hover/select/back, and a quiet ambience per biome.
- **PIP voice:** short typed-text blips for PIP's lines (tutorial, briefing, taunts), with a pitch for each mood.
- **Tests:** every loop is seamless (first and last samples match), peak and loudness stay in range, and
  `docs/AUDIO.md` lists every asset. The owner listens and sends notes.

### Phase 3: backgrounds and main menu (release 0.19.0)

- **Altitude sky:** the climb is the point of the game, so the sky changes with the level number: storm cloud
  and ember glow at the bottom, then dawn, then thin cold air, then stars. Each act keeps its own skyline on top
  of that.
- **Depth:** three to five parallax layers per act, with slow ambient motion: embers (Cinder), sparks
  (Scrapyard), snow (Freezer), rain and lightning (Storm), forge glow (Forge), steam (Underworks), tears in the
  air (Rift), and a heartbeat pulse (Core).
- **Main menu:** a living scene. The Spire and the moon are already there; add drifting clouds, a day phase
  that changes with the real clock, small details around the ledge, and a background that shows the highest act
  the player has reached. Menu buttons get entrance and press animations.
- **Proof:** the capture tool (`tools/capture_round2.gd`) shoots every act's background and the menu, one at a
  time, and the owner reviews them as a contact sheet.

### Phase 4: animation (release 0.19.0)

- **Audit first:** list every animated thing (Trevor's sheet, enemies, hazards, bosses, UI) and what is missing.
- **Trevor:** anticipation and squash on jump and landing, a proper run cycle with dust, wall-slide sparks, a
  dash afterimage, a death that shatters into pixels, and a respawn that "re-rolls" with a glitch-scramble
  effect, because the rebuilding level is the game's signature.
- **World:** idle animation for every hazard and enemy, boss entrance beats, act title cards, a nicer door and
  gate.
- **UI:** transitions between menu pages, button feedback, number count-ups, and the results card.
- **Rule:** nothing flashes harder than the existing Reduce Motion settings allow; each new effect respects
  them.

### Phase 5: tutorial and story (release 0.19.0)

- **Tutorial:** a more interesting PIP. A ghost Trevor demonstrates each move before the player tries it, PIP
  speaks with the new blips, each set ends with a short mini challenge, and a graduation course at the end
  uses everything. It stays skippable and replayable from the menu.
- **Story film:** from 45 seconds to about 75 to 90, with a slow camera, letterbox bars, layered parallax,
  particles, glow, timed sound and music, and captions that follow the music. It stays skippable. The ending
  film gets the same treatment. The owner reviews each film as a recording before it replaces the old one.
- **Act intros:** a short title card with the act's colour, name and skyline, so each act feels like a place.

### Phase 6: moves with purpose (release 0.20.0)

Every move is needed somewhere, so none of them is decoration.

| Move | A piece that needs it |
| --- | --- |
| Dash | a gap too wide for any jump |
| Spin (double jump) | a ledge too high to reach, with no wall to climb |
| Wall-jump | a shaft with no floor until the top |
| Slide | a crusher or laser too low to pass standing |
| Ground pound | a cracked floor that is the only way down |
| Grapple | a void with an anchor and nothing to land on |
| Slash | a drone or barrier that blocks the only route |

One required piece per move in the machine generator, introduced in the act that teaches the move and mixed
in later. The bot clears each piece with the move and fails it without (the negative control).

### Phase 7: difficulty and level 15 (release 0.20.0)

The owner's drawing: two or three tall walls with obstacles and zig-zag jumping, just before and just after
boss levels. They are fixed shapes inside the rolled levels, their obstacles re-roll on each death, and the bot
proves them like every other piece. Starts when the drawings arrive.

### Phase 9: trailer and GIFs (release 0.99.0)

Made after the look and sound are final, so it shows the real game.
1. In-engine captures with Godot's Movie Maker mode (`--write-movie`): 60 fps at 1080p and 4K, scripted shots

2. The owner's OBS footage for moments a script cannot fake.
3. Edit with ffmpeg: the studio card, 45 to 60 seconds of play cut to the new music, the logo, and "Play free

Tools already on this PC: ffmpeg, OBS, and Movie Maker inside Godot. Optional: `winget install gifski` for

## 4b. The quality gate (every release, added 2026-11-18)

Nothing ships until all of this is done, in this order. It is light on the PC: two Godot processes at most, at
idle priority.

1. **Backend test and hardening.** For the updater: `python -m pytest launcher/tests`, `test_update_rules`,
   `test_game_updater`, and the live run `tools/run_updater_live.ps1` against the fake GitHub. Any change to the
   updater or the launcher gets a security read first (`docs/SECURITY_REVIEW_updater.md` is the model).
2. **Code audit.** A light review of the release's diff (correctness, leftovers, simplification), then the
   full suite list on a snapshot copy with two runners. Known and accepted: the old `test_level` item.
3. **Visual audit.** `tools/capture_round2.gd` shots of the title, About, Settings, the update notice, one level
   per act and the pages touched by the release, one at a time, reviewed as a contact sheet. What was seen and
   what was only tested are reported separately.
4. **Launcher polish.** The launcher gets the same look as the game and the brand kit, the updater page shows real
   progress and patch notes, and the known wordmark bundling bug stays fixed.
5. **Clean-PC check of every build.** A fresh folder and a fresh user-data folder, nothing from the dev machine:
   - Windows: unzip, run the launcher, play a level, quit, update from the previous release to this one, check
     the rollback copy.
   - Web: the itch page on a clean browser profile, and the offline zip through its local server.
   - macOS and Linux: the zip layout, the executable bit and the README (these cannot be run on this PC, so the
     report says so).

6. **Leave no trace** (added 2026-11-18 after a test install of mine was run by the owner and showed a confusing
   error). Nothing a test, capture or build creates may outlive the step that made it:
   - test and capture folders live only in `%TEMP%` under this project's prefixes (`ap_`, `ascent_`, `some_test_`,
     `b_test_`) and every script removes them in a `finally`; a stand-in install is never left anywhere the owner could
     run it by hand;
   - scripts stop only the processes they started (by their own process object or by the path of their own work
     folder), never by name;
   - after every work session and every release run `tools\clean_stale.ps1 -Keep <current version> -Apply`. It removes
     old release builds, staging copies, old logs, caches and test leftovers, and it never touches the licensed font
     (`assets\fonts`, not in git), the music source, `.godot`, `version.txt`, or anything outside this project's names;
   - never run a blanket `git clean -X` here: it would delete the licensed font.

## 5. Suggestions that add the most value

1. **The altitude sky** (phase 3) ties the visuals to the title. It costs little and the whole game feels
   like a climb.
2. **Adaptive music and PIP blips** (phase 2) make deaths and boss chases feel authored, not looped.
3. **A re-roll effect on respawn** (phase 4) turns the main mechanic into something you can see and hear.
4. **A menu that remembers progress** (phase 3): the background shows the highest act reached, so coming back
   to the game feels like coming back to the climb.
5. **A local stats page** (optional, after 0.20.0): deaths, best times and cores per level, and a "most
   deaths" level. It gives players a reason to compare and screenshot.
6. **Screenshot regression** (quality): the capture tool already exists, so each release can compare every
   act's background to the last one and flag accidental changes.
7. **A devlog on itch for each release** (marketing): short posts keep the page in the "recently updated" feeds.
