# Protection, license keys, auto-update, launcher and pricing (design, 2026-11-15)

Owner brief: price 10 USD / 900 INR; strong copyright and a key system that is hard to crack; auto-update without leaving the app; a better launcher; better visuals. This file is the design. Parts marked BUILT exist in the repo with tests; everything else is a plan.

## 0. The honest limit
No client-side protection is uncrackable: the game runs on the buyer's machine, so a determined cracker can always patch the check out. Games sell anyway, because the goal is to make cracking cost more than 10 USD of effort, to make a crack ship late and break on every update, and to make leaks traceable. Everything below raises that cost in layers. Anyone who promises "uncrackable" is selling something.

Also: the game is a one-person, single-player 10 USD title. The biggest piracy lever is not DRM, it is convenience and price: a store page with a demo, easy updates, and a price that is fair in India (900 INR is about 10 USD; consider regional pricing, e.g. 399-499 INR, because regional piracy falls sharply when the local price matches local income).

## 1. Where to sell (decides how much we must build)
| Channel | DRM we get for free | Notes |
|---|---|---|
| Steam | Steamworks DRM wrapper (light), Steam auth, auto-update, cloud saves | 30% cut, 100 USD app fee, strongest update story, best protection per effort |
| itch.io | Download keys, butler patches, itch app auto-update | 10% (adjustable), our own key system still useful for direct sales |
| Own site (Lemon Squeezy / Gumroad / Razorpay for INR) | Nothing: we build keys | Needs the licence server in section 3 |
Recommendation: Steam + itch for the paid game (their update and key machinery is free and mature), plus our own signed keys for direct sales, press copies and testers. The rest of this plan is what we build for the direct channel and for the launcher.

## 2. License keys (BUILT: verification; PLAN: issuing server)
- Format: `PA1.<base64url payload>.<base64url RSA-2048 signature>`; payload `{v, id, ed (full|tester|press), iat, exp}`.
- The game holds only the PUBLIC key (`assets/license_public.pem`, to be generated by `python tools/license_tool.py keygen`). The PRIVATE key lives offline and signs keys; a key cannot be forged without it. BUILT: `scripts/license_key.gd` (offline verify), `tools/license_tool.py` (keygen, make-key, verify, sign-manifest), `tests/test_license.gd` (genuine, expired, tampered, wrong key, junk all covered).
- Edition rules: `full` unlocks everything; `tester` expires (14 days) and shows a TESTER watermark; `press` is for reviewers/YouTubers, no expiry but revocable.
- PLAN, the licence server (serverless, about 150 lines, free tier): `POST /activate {key, device_hash}` returns a signed activation `{id, device_hash, iat}`; limit 2 devices per key; `POST /revoke` (owner only) adds an id to a signed revocation list the game fetches. The game then needs the network only at activation and every 14 days (offline grace 30 days), so legitimate players are never locked out by an outage.
- Privacy: the device hash is a salted SHA-256 of hardware ids; no name, no email in the key; this goes in the EULA/privacy text.

## 3. Making it hard to crack (layers, cheapest first)
1. **Encrypted PCK + scripts**: Godot export with a 256-bit encryption key (a custom engine build holds the key; the stock export templates cannot). Stops casual asset/script extraction. The key sits in the binary, so this raises effort, it does not stop a determined reverse engineer.
2. **Check in many places, not one**: no single `if licensed` to patch. Verify at boot, on level start, on clear, on save; each failure degrades quietly after a delay (a random later level shows the TESTER watermark and then refuses to load new levels) instead of an obvious "invalid key" dialog that tells the cracker which check to patch.
3. **Integrity**: hash the game's own scripts/PCK at runtime against a signed list (the same RSA machinery as updates); a patched PCK fails the signature.
4. **Per-copy watermark**: the licence id is woven into the build as invisible markers (a tiny per-id variation in a couple of constants and a hidden line of the credits). A leaked copy can be traced to the key and revoked. Cheap, and the strongest deterrent for press copies.
5. **Online revalidation + revocation list** (section 2).
6. **Release hardening**: strip symbols, sign the Windows exe (Authenticode certificate, also needed to avoid SmartScreen scares), obfuscate the launcher (PyInstaller + bytecode encryption is weak; prefer a small Rust/Go launcher for the paid build).
7. **Legal**: copyright notice in every file header and the credits, an EULA that forbids redistribution and modification, DMCA takedown template ready, register copyright where cheap (India: Copyright Office, low fee; US registration optional but needed before suing). This is not legal advice; have a lawyer review the EULA before launch.
Rejected: kernel anti-cheat, always-online-only DRM, and code virtualizers (Denuvo-class): cost, false positives and bad reviews outweigh the benefit for a 10 USD indie game.

## 4. Auto-update without leaving the app (PLAN)
- Update manifest `manifest.json`: `{version, notes, files: [{path, sha256, size, url}]}`, signed with the same private key (`tools/license_tool.py sign-manifest`), detached signature `manifest.json.sig`.
- The launcher (and a small in-game "UPDATE AVAILABLE" panel in Settings) fetches the manifest over HTTPS, verifies the RSA signature with the baked-in public key, compares versions, downloads only changed files (file-level delta first; binary delta later), checks each SHA-256, stages them in `updates/`, and swaps on next launch (a Windows file cannot replace itself while running). A failed or partial download never replaces a working install; one rollback copy is kept.
- Channels: `stable` and `tester` manifests; testers can opt into the tester channel in Settings. Hosting: GitHub Releases or any static host; the signature means the host does not need to be trusted.
- Web build: updates are automatic (the browser fetches the new build); no work needed.
- Steam/itch builds use their own updaters; ours is for the direct/portable build.

## 5. Launcher quality (PLAN)
Today: Python/Tk launcher built with PyInstaller (`tools/build_launcher.py`), known cosmetic packaging bug (wordmark falls back to text). Upgrade path: (a) fix the asset bundling, (b) add the update flow of section 4 with a progress bar, (c) news/patch notes panel from the manifest, (d) key entry + activation screen, (e) settings shortcuts (display, tester mode), (f) signed exe. A rewrite in Godot itself (launcher as a scene in the same export) is an option to share fonts and art.

## 6. Visual upgrade (PLAN, after the first paid candidate)
Priorities by player impact: (1) player and hazard sprite pass and animation polish (hit stop, squash and stretch, landing dust, death burst); (2) per-biome backdrops and parallax; (3) HUD and menu polish (the visor frame is done; add the key/activation and update screens); (4) store art and a trailer (the YouTuber footage is the first trailer). Tile art for the 8 biomes is already procedural (`tile_decor.gd`).

## 7. Pricing
10 USD / 900 INR as the list price; recommend launch pricing (20-30% off for 2 weeks), regional pricing on Steam and itch (India, Brazil, Turkey, SEA), a free web demo of levels 1-10 (also the best anti-piracy tool), and bundle/discount keys via the signed `press` edition. Refund-risk and quit-curve notes are in `docs/PLAN_v2_big_run_2026-10-20.md`.

## 8. Order of work (so the YouTuber release is not blocked)
1. NOW (this week): ship the 0.16.0 tester build as a free tester/press build (no DRM, `--tester` telemetry), so the YouTuber footage and tester data arrive before launch. Nothing in sections 3-5 is needed for that.
2. Before the paid launch: generate the shipping key pair; wire LicenseKey into boot/level/clear/save with the silent-degrade rule; per-copy watermark; Godot custom build with PCK encryption; signed exe.
3. Updater: manifest signing (BUILT in the tool) then launcher download/verify/swap, then the in-game panel.
4. Licence server for direct sales; Steam/itch pages (use their DRM and updaters).
5. EULA and copyright text reviewed by a lawyer; DMCA template.
6. Visual upgrade passes in parallel; art direction doc update.
